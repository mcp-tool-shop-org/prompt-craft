#

**画像に何が含まれている必要があるかを指定します。それが含まれているか確認し、そうでない場合は拒否します。**

生成的な画像パイプラインは、間違った顔や色使いで、派閥のマークが一切ないヒーローを喜んで提供し、さらに成功したと報告します。なぜなら、何も問題がないように見えるからです。プロンプト作成は、不透明な文章によるプロンプトを、**表現可能な主張の型付き契約**に置き換え、同じリストを2回使用します。1回目はプロンプトを作成するために、2回目はピクセルを確認するために使用し、**必要な主張が存在しない場合はアセットをブロックします。**

```
   CONTRACT  ──atoms──▶  SYNTHESIZE  ──prompt──▶  GENERATE
   typed, depictable     every token traces      diffusion + control
        │                to an atom                     │
        │ the same atoms                                │ pixels
        └──────────────────────▶  GATE  ◀───────────────┘
                    a DIFFERENT model family checks the
                    contract against the image, cheapest
                    tier deciding first
                         │                    │
                       PASS                FAIL / UNCERTAIN
                         ▼                    ▼
                    BIND to canon      REPAIR ladder, or a
                  (only when every     human checkpoint when
                   required atom       the gate is unsure
                   actually passed)
```

**基本的な考え方：** 契約の原子リストは、*2回使用される同じリストです。* プロンプトの作成と結果の確認は、同じソースから読み取られるため、要求されたものが検証されるのは、まさにそのものです。これにより、不透明なプロンプトが残す余地がなくなり、一連の流れが閉じられます。

## インストール

```bash
pip install prompt-crafter
pcraft --help
```

```bash
npm install -g @mcptoolshop/prompt-crafter   # the same command, as a launcher
```

このパッケージは**`prompt-crafter`**です。なぜなら、`pcraft`と`prompt-craft`の両方がPyPIで利用可能であり、インポートするパッケージとコマンドは`pcraft`のままです。npmパッケージは**移植ではなく、ランチャー**です。別の言語で閾値を再実装すると、閾値が変動するため、真の値を持つPythonに転送し、その終了コードを継承します。

開発用：

```bash
pip install -e ".[dev]"
```

コアは**GPUを使用せず、どこでも実行できます。** 完全にテストスイートを実行すると、モックジェネレーターと検証器に対して実行され、プラグインの境界が実際に機能することが証明されます。追加のパッケージ（torch/diffusers）`[image]`と（DSPy + ホストされたLM）`[synth]`は、実際のジェネレーター、検証器、および合成器に接続します。**コアを実行、テスト、または評価するには、これらは必要ありません。**

```bash
pcraft demo              # the whole loop end-to-end, no GPU, deterministic stubs
pcraft list              # contract ids in the store
pcraft validate          # resolve + compile the question DAG, no generate
pcraft gate <image>      # check an image against a contract
pcraft recipe            # emit the Cloud Kontext + fist-only Fill graph
pcraft replay <record>   # re-read a bound asset's provenance receipt
```

## 契約の形式

文章によるプロンプトではありません。**原子的で、表現可能で、個別に検証可能な**主張のリストです。

- **`must_have`** — 衣服、色使い、シルエット、シンボル。それぞれに、どのゲート層がそれを検証するかを示す`check_type`、スコア`severity`があり、オプションで親が合格した場合にのみ意味を持つようにする`depends_on`エッジがあります。存在しない斧の色を検証しても意味はありません。
- **`must_not`** — 制約の反転。ピクセル上に**存在しないこと**として検証されます。否定的なプロンプトではありません。否定的なプロンプトは、残存する特徴を残し、言い換えに陥る可能性があります。
- **`identity_ref`** — 参照画像。**アイデンティティは条件であり、トークンではありません。** 解剖学的なテキストは、拡散モデルに標本をレンダリングさせます。参照画像は、特定の顔を固定します。

契約は継承されます。キャラクターは派閥を拡張し、継承は**フェイルクローズ**です。子要素は要件を*追加*できますが、継承したものを緩和したり、黙って削除したりすることはできません。

## ゲート

3つの層があり、最も安価なものが最初に決定し、安価な答えが明確でない場合にのみ段階的に進みます。依存関係の順にパスを実行すると、失敗した親は、ナンセンスをスコアリングするのではなく、子要素をN/Aとしてマークします。

**検証器は常にジェネレーターとは異なるモデルファミリーであり、そうでない場合は実行を拒否するガードによって強制されます。** モデルは、自身の出力の優れた判断者ではありません。これは、この設計の中で最も推測の少ない部分です。

**終了コードは4つの異なるものを区別します。** 呼び出し元が1つの番号を読み取る必要があるため、それらを区別する必要があります。

| 終了 | 意味 |
|---|---|
| `0` | ゲートが実行され、必要なすべての原子が合格しました |
| `1` | 無効な引数または形式の誤った契約 |
| `2` | 実行されましたが、必要な原子が**失敗しました** |
| `3` | 実行されましたが、結果は**確認されていません** — 人間のバンド |
| `4` | **実行できませんでした。** 読み取り可能な入力がないか、必要な層が利用できません。 |

最後の行が重要です。「チェックできません」と「チェックして問題がある」は異なる事実であり、それらをまとめてしまうことは、実際に害を及ぼすことが文書化されています。そのため、ブラウザは証明書の失効をソフトフェイルさせ、監視標準では1990年代から明確な*不明*の判断が採用されています。すべてのゲートトランスクリプトには、**実際に実行された必要な層の数**も、判断とは別に記録されるため、静かにチェックを停止したゲートは、合格として解釈することはできません。

**CLIPScoreは、ゲートメトリックとしては使用されません。** 概念の集合体として機能し、どの属性がどのオブジェクトに属するか、数、および関係を認識しません。検証器インターフェイスには、既知の不具合であることが文書化されているため、誰も再導入することはありません。

## 信頼性と脅威モデル

- **アクセスされるデータ**：指定するJSON形式の契約、入力する画像、および指定したディレクトリに書き込まれるプロベナンスレコードです。それ以外のデータは読み込まれません。
- **アクセスされないデータ**：いかなる種類の認証情報も読み込まれたり、保存されたり、送信されたりすることはありません。**テレメトリー、分析、または使用状況の追跡は行いません**。オプトアウトする必要がないのは、オプトアウトする対象が存在しないためです。コアはネットワークライブラリを一切インポートしません。
- **ネットワークからのデータ送信**：コアからは何も送信されません。オプションの`[image]`と`[synth]`の追加モジュールは、その性質上、モデルホストにアクセスします。それが唯一のネットワークパスであり、それらをインストールするかどうかは選択できます。
- **権限**：通常のユーザー権限のみが必要です。昇格、サービスインストール、レジストリまたはシステム設定への書き込みは行いません。
- **重要な点（主張するのではなく、明示的に開示）**：**ファイル操作はサンドボックス化されていません。**`--records-dir`と`--db`は、指定された場所に意図的に書き込みます。これはローカルファーストツールであるためです。目的の場所に指定してください。
- **エラー**：意図的な拒否には、コード、メッセージ、およびヒントが含まれており、**例外を発生させます（`assert`ではなく）**。そのため、`-O`はそれらを削除できません。スイートは、それを証明するために、`-O`の下で2回実行されます。予期しないエラーが発生した場合、トレースバックは`--debug`でのみ出力されます。

## サポート状況

`main`のみがサポートされている状態です。リリースチャネル、バックポートポリシー、SLAはありません。これは、オープンに公開されたスタジオインフラストラクチャであり、サポート契約を結んだ製品ではありません。

## 各要素の配置方法

`core/`はドメインに依存せず、拡散またはPyTorchシンボルを一切インポートしません。ドメインプラグインは、ジェネレーター、検証者のリスト、およびエンコーダールールセットという3つのものをエクスポートします。新しいドメインを追加するには、`domains/`の下に新しい兄弟要素を作成します。`core/`のいずれも変更されません。GPUを使用しないスイートが、その主張を正直なものにします。

```
src/pcraft/
  core/          contract · loop · gate · synth · optimize · receipt   (GPU-free)
  cli/           pcraft: synth | gate | bind | list | validate | demo | replay | doctor | schema | recipe | compile | sync-rules
  domains/       ── PLUGIN BOUNDARY ──
    image/       generators, the three verifier tiers, encoder rules, sprite subdomain
```

`domains/image/rules/`の下にあるエンコーダールールは、**検証済みのレシピデータベースから生成される**ものであり、手書きではありません。また、生成ヘッダーが含まれています。バインドされたすべての資産は、契約ハッシュ、シンセサイザーアーティファクト、ジェネレーターとシード、検証者バージョン、および完全なアトムごとのゲートトランスクリプトを記録する**再現可能なプロベナンスレシート**を書き込みます。

設計の根拠、このリポジトリが評価される基準、およびすべての不可逆的なアクションに対する名前付きの修正は、[`STANDARDS.md`](STANDARDS.md)と[`COMPENSATORS.md`](COMPENSATORS.md)に記載されています。
