#

**画像に何が含まれている必要があるかを指定します。それが含まれているか確認し、そうでない場合は拒否します。**

生成的な画像パイプラインは、間違った顔や配色で、また派閥のマークが一切ないヒーローを喜んで提供し、さらに成功したと報告します。なぜなら、何も問題がないように見えるからです。プロンプト作成は、不透明な文章によるプロンプトを、**表現可能な主張の型付き契約**に置き換え、同じリストを2回使用します。1回目はプロンプトを作成するために、2回目はピクセルを確認するために使用し、**必要な主張が存在しない場合はアセットをブロックします。**

```
   CONTRACT  ──atoms──▶  SYNTHESIZE  ──prompt──▶  GENERATE
   typed, depictable     every token traces      diffusion + control
        │                to an atom                     │
        │ the same atoms                                │ pixels
        └──────────────────────▶  GATE  ◀───────────────┘
                    a DIFFERENT model family checks the
                    contract against the image, cheapest
                    tier deciding first
                         │                    │
                       PASS                FAIL / UNCERTAIN
                         ▼                    ▼
                    BIND to canon      REPAIR ladder, or a
                  (only when every     human checkpoint when
                   required atom       the gate is unsure
                   actually passed)
```

**基本的な考え方：** 契約の原子リストは、*2回使用される同じリストです。* プロンプトの作成と結果の確認は、どちらも同じソースから読み取られるため、要求されたものが検証されます。これにより、不透明なプロンプトが残す余地がなくなり、一連の流れが閉じられます。

## インストール

```bash
pip install prompt-crafter
pcraft --help
```

```bash
npm install -g @mcptoolshop/prompt-crafter   # the same command, as a launcher
```

このパッケージは**`prompt-crafter`**です。なぜなら、`pcraft`と`prompt-craft`の両方がPyPIで利用可能であり、インポートするパッケージとコマンドは`pcraft`のままです。npmパッケージは**ポータブルではなく、ランチャー**です。別の言語で閾値を再実装すると、閾値が変動するため、真の値を持つPythonに転送し、その終了コードを継承します。

開発用：

```bash
pip install -e ".[dev]"
```

コアは**GPUを使用せず、どこでも実行できます。** 完全にテストスイートを実行すると、モックジェネレーターと検証器に対して実行され、プラグインの境界が実際に機能することを確認します。`[image]`（torch/diffusers）および`[synth]`（DSPy + ホストされたLM）の追加パッケージは、実際のジェネレーター、検証器、および合成器を接続します。**コアを実行、テスト、または評価するには、これらは必要ありません。**

```bash
pcraft demo              # the whole loop end-to-end, no GPU, deterministic stubs
pcraft gate <image>      # check an image against a contract
pcraft replay <record>   # re-read a bound asset's provenance receipt
```

## 契約がどのようなものか

文章によるプロンプトではありません。**原子的で、表現可能で、個別に検証可能な**主張のリストです。

- **`must_have`** — 衣服、配色、シルエット、シンボル。それぞれに`check_type`（どのゲート層がそれを検証するか）、`severity`、およびオプションで`depends_on`のエッジが含まれており、これにより、ある主張は親が合格した場合にのみ意味を持ちます。存在しない斧の色を検証しても意味はありません。
- **`must_not`** — 制約の反転。ピクセル上に**存在しないこと**として検証されます。否定的なプロンプトではありません。否定的なプロンプトは残存する特徴を残し、言い換えられてしまいます。
- **`identity_ref`** — 参照画像。**アイデンティティは条件付けであり、トークンではありません。** 解剖学的なテキストは、拡散モデルに標本をレンダリングさせます。参照画像は、特定の顔を固定します。

契約は継承されます。キャラクターは派閥を拡張し、継承は**フェイルクローズ**です。子要素は要件を*追加*できますが、継承したものを緩和したり、黙って削除したりすることはできません。

## ゲート

3つの階層があり、最も安価なものが最初に決定し、安価な答えが明確でない場合にのみ、より高度なものにエスカレートします。依存関係の順序でパスを実行するということは、失敗した親要素は、ナンセンスをスコアリングするのではなく、子要素をN/Aとしてマークすることを意味します。

**検証器は常にジェネレーターとは異なるモデルファミリーであり、そうでない場合は実行を拒否するガードによって強制されます。** モデルは、自身の出力の優れた判断者ではありません。これは、この設計の中で最も推測の少ない部分です。

**終了コードは4つの異なるものを区別します。** なぜなら、1つの番号を読み取る呼び出し元は、それらを区別する必要があるからです。

| 終了 | 意味 |
|---|---|
| `0` | ゲートが実行され、必要なすべての原子が合格しました |
| `1` | 無効な引数または形式の誤った契約 |
| `2` | 実行されましたが、必要な原子が**失敗しました** |
| `3` | 実行されましたが、結果は**確認されていません** — 人間のバンド |
| `4` | **実行できませんでした。** 読み取り可能な入力がないか、必要な階層が利用できません。 |

最後の行が重要です。「チェックできません」と「チェックして問題がある」は異なる事実であり、それらをまとめてしまうことは、実際に害を及ぼすことが文書化されています。そのため、ブラウザは証明書の失効をソフトフェイルし、監視標準では1990年代から明確な*不明*の判断が採用されています。すべてのゲートトランスクリプトには、**実際に実行された必要な階層の数**も、判断とは別に記録されるため、静かにチェックを停止したゲートは、合格として解釈することはできません。

**CLIPScoreは、ゲートメトリックとしては使用されません。** 概念の集合体として機能し、どの属性がどのオブジェクトに属するか、数、および関係を認識しません。検証器インターフェイスには、既知の不具合であることが文書化されているため、誰も再導入することはありません。

## 正直なステータス

**v0.2.0 — コアは本物です。GPUパスはここで実行されたことはありません。**

| | |
|---|---|
| コア | **105個のテストが合格し、GPUを使用せず、決定論的です。** `verify`を実行すると、スイートが実行され、次に`-O`の下でスイートが再度実行され、パッケージがビルドされます。 |
| 述語 | `core/`の11個の複合的な決定ポイントは**ミューテーションテスト**されています。21個のうち20個のミュータントが排除され、[残りのミュータントの名前](scripts/mutate_predicates.py)は隠されていません。 |
| カバレッジ | 全体で81％です。GPUに依存するジェネレーターと検証器のアダプターが、テストされていない残りの部分です。 |
| `[image]`パス | **このマシンでは実行されません。** `bind --no-mock`は、依存関係がないというエラーで拒否します。プラグイン境界より下のものはすべて、測定によって検証されていません。 |
| 閾値 | スプライトサブゲートの最小値と分散の制限は、**記録されたキャリブレーションのないハードコード化されたデフォルトです。** ホールドアウトや引用はありません。これらはプレースホルダーとして扱ってください。 |
| 実際のカノン | 出荷されるサンプル契約は、**一般的な発明であり、実際のプロジェクトのカノンではありません。** 実際のカノンをバインドすることは、意図的な人間の決定です。 |

このドキュメントの以前のバージョンで述べられており、測定によってサポートされなかった2つの主張について、ここでは修正し、黙って削除するのではなく：

- 3つの閾値は、「人間がラベル付けしたホールドアウトデータに基づいて調整された」と説明されています。しかし、そうではありません。これらはデフォルト値です。
- 生成モデルは決して自分自身のゲートにはならないというルールは、研究によってそれが証明されたかのように述べられています。それを裏付ける証拠は、直接的なものではなく**収束的**です。つまり、二者択一の識別的なポーリングは、自由形式のキャプション生成よりも測定可能な限り安定しており、モデルは外部からのフィードバックなしでは確実に自己修正できず、自己認識は自己選好バイアスを追跡します。単独の研究で直接比較が行われるわけではありません。このルール自体は妥当ですが、その確実性は誇張されています。

## 信頼性と脅威モデル

- **アクセスされるデータ**：指定されたJSON形式の契約データ、入力する画像、および指定したディレクトリに書き込まれるプロベナンスレコードです。それ以外のデータは読み込まれません。
- **アクセスされないデータ**：あらゆる種類の認証情報は読み込まれたり、保存されたり、送信されたりしません。**テレメトリ、分析、または使用状況の追跡も行いません**。オプトアウト機能がないのは、オプトアウトする対象が存在しないためです。コアはネットワークライブラリを一切インポートしません。
- **ネットワークへのデータ送信**：コアからは何も送信されません。オプションの`[image]`と`[synth]`の追加モジュールは、その性質上、モデルホストにアクセスします。これが唯一のネットワーク経路であり、それらをインストールするかどうかは選択できます。
- **権限**：通常のユーザー権限のみが必要です。管理者権限の昇格、サービスへのインストール、レジストリまたはシステム設定への書き込みは行いません。
- **重要な点（隠蔽するのではなく、明示的に開示）**：**ファイル操作はサンドボックス化されていません。**`--records-dir`と`--db`は、指定された場所に意図的に書き込みます。これはローカル優先のツールであるためです。書き込む場所を慎重に選択してください。
- **エラー**：意図的な拒否には、コード、メッセージ、およびヒントが含まれ、**例外を発生させます（`assert`ではなく）**。そのため、`-O`はそれらを削除できません。スイートは、そのことを証明するために、`-O`の下で2回実行されます。予期しないエラーが発生した場合、トレースバックは`--debug`でのみ出力されます。

## サポート状況

`main`のみがサポート対象の状態です。リリースチャネル、バックポートポリシー、SLAはありません。これは、オープンに公開されているスタジオインフラストラクチャであり、サポート契約を結んだ製品ではありません。

## コンポーネントの構成方法

`core/`はドメインに依存せず、拡散またはPyTorchシンボルを一切インポートしません。ドメインプラグインは、ジェネレーター、検証者のリスト、およびエンコーダールールセットという3つの要素をエクスポートします。新しいドメインを追加するには、`domains/`の下に新しいサブモジュールを作成します。`core/`の内容は変更されません。GPUを使用しないスイートが、この主張の妥当性を保証しています。

```
src/pcraft/
  core/          contract · loop · gate · synth · optimize · receipt   (GPU-free)
  cli/           pcraft: synth | gate | bind | demo | replay | compile | sync-rules
  domains/       ── PLUGIN BOUNDARY ──
    image/       generators, the three verifier tiers, encoder rules, sprite subdomain
```

`domains/image/rules/`内のエンコーダールールは、**検証済みのレシピデータベースから生成される**ものであり、手動で記述されたものではありません。また、生成ヘッダーが含まれています。バインドされたすべての資産は、契約ハッシュ、シンセサイザーアーティファクト、ジェネレーターとシード、検証者バージョン、および完全なアトムごとのゲートトランスクリプトを記録する**再現可能なプロベナンスレシート**を書き込みます。

設計の根拠、このリポジトリが評価される基準、およびすべての不可逆的なアクションに対する対応策は、[`STANDARDS.md`](STANDARDS.md)と[`COMPENSATORS.md`](COMPENSATORS.md)に記載されています。
