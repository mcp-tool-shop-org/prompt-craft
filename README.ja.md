#

**画像に何が含まれている必要があるかを指定します。それが含まれているか確認し、そうでない場合は拒否します。**

生成的な画像パイプラインは、間違った顔や配色で、さらに派閥のマークが一切ないヒーローを喜んで提供します。そして、何も表示されなかったため、成功したと報告します。プロンプト作成においては、不透明な文章形式のプロンプトを、**表現可能な要素に関する明確に定義された契約書**に置き換え、同じリストを2回使用します。1回はプロンプトを作成するために、もう1回はピクセルを確認するために使用し、**必要な要素が存在しない場合はアセットの使用をブロックします。**

```
   CONTRACT  ──atoms──▶  SYNTHESIZE  ──prompt──▶  GENERATE
   typed, depictable     every token traces      diffusion + control
        │                to an atom                     │
        │ the same atoms                                │ pixels
        └──────────────────────▶  GATE  ◀───────────────┘
                    a DIFFERENT model family checks the
                    contract against the image, cheapest
                    tier deciding first
                         │                    │
                       PASS                FAIL / UNCERTAIN
                         ▼                    ▼
                    BIND to canon      REPAIR ladder, or a
                  (only when every     human checkpoint when
                   required atom       the gate is unsure
                   actually passed)
```

**基本的な考え方：** 契約書のアトムリストは、*2回使用される同じリストです。* プロンプトの作成と結果の確認は、同じソースから読み取られるため、要求されたものが検証されます。これにより、不透明なプロンプトでは解決できない問題が解消されます。

## インストール

```bash
pip install prompt-crafter
pcraft --help
```

```bash
npm install -g @mcptoolshop/prompt-crafter   # the same command, as a launcher
```

このソフトウェアの配布パッケージは**`prompt-crafter`**です。なぜなら、`pcraft`と`prompt-craft`の両方がPyPIで利用可能であり、インポートするパッケージとコマンドは`pcraft`のままです。npmパッケージは、**移植版ではなくランチャー**です。別の言語で閾値を再実装すると、閾値が変動するため、Pythonに処理を転送し、その終了コードを引き継ぎます。

開発用：

```bash
pip install -e ".[dev]"
```

コア部分は**GPUを使用せず、どこでも実行できます。** 完全にテストスイートを実行するには、モックジェネレーターとベリファイアを使用します。これにより、プラグインの境界が実際に機能することが証明されます。`[image]`（torch/diffusers）および`[synth]`（DSPy + ホストされたLM）の追加パッケージは、実際のジェネレーター、ベリファイア、およびシンセサイザーを接続します。**コアを実行、テスト、または評価するには、これらは必要ありません。**

```bash
pcraft demo              # the whole loop end-to-end, no GPU, deterministic stubs
pcraft gate <image>      # check an image against a contract
pcraft replay <record>   # re-read a bound asset's provenance receipt
```

## 契約書がどのようなものか

文章形式のプロンプトではありません。**原子的で、表現可能で、個別に検証可能な**要素のリストです。

- **`must_have`** — 衣服、配色、シルエット、シンボル。それぞれに`check_type`（どのゲート層がそれを検証するか）、`severity`、およびオプションで`depends_on`のエッジが含まれます。これにより、要素は親要素が合格した場合にのみ意味を持ちます。存在しない斧の色を検証しても意味はありません。
- **`must_not`** — 制約条件の反転。ピクセル上に**存在しないこと**として検証されます。否定的なプロンプトではありません。否定的なプロンプトでは、残存する特徴が残り、言い換えられてしまいます。
- **`identity_ref`** — 参照画像。**アイデンティティはコンディションであり、トークンではありません。** 解剖学的なテキストを使用すると、拡散モデルは標本をレンダリングします。参照画像は、特定の顔にバインドされます。

契約書は継承します。キャラクターは派閥を拡張し、継承は**フェイルクローズド**です。子要素は要件を*追加*できますが、継承したものを緩和したり、黙って削除したりすることはできません。

## ゲート

3つの階層があり、最も安価なものが最初に決定し、安価な答えが明確でない場合にのみ、より高度なものにエスカレートします。依存関係に基づいてパスを処理するため、失敗した親要素は、ナンセンスなスコアを与えるのではなく、子要素をN/Aとしてマークします。

**ベリファイアは常にジェネレーターとは異なるモデルファミリーです。** これは、そうでない場合は実行されないようにするガードによって強制されます。モデルは、自身の出力の優れた評価者ではありません。これは、この設計の中で最も推測の少ない部分です。

**終了コードは4つの異なるものを区別します。** 呼び出し元が1つの数字を読み取る必要があるため、それらを区別する必要があります。

| 終了 | 意味 |
|---|---|
| `0` | ゲートが実行され、必要なすべての要素が合格しました。 |
| `1` | 無効な引数または形式の誤った契約書 |
| `2` | 実行されましたが、必要な要素が**失敗しました** |
| `3` | 実行されましたが、結果は**確認されていません** — 人間のバンド |
| `4` | **実行できませんでした。** 読み取り可能な入力がないか、必要な階層が利用できません。 |

最後の行が重要です。「チェックできなかった」と「チェックして問題がある」は異なる事実であり、これらをまとめてしまうことは、実際に害を及ぼすことが文書化されています。これが、ブラウザが証明書の失効をソフトフェイルさせる理由であり、監視標準では1990年代から明確な*不明*の判断が採用されている理由です。すべてのゲートトランスクリプトはまた、**実際に実行された必要な階層の数**も、判断とは別に報告します。したがって、静かにチェックを停止したゲートは、合格として解釈することはできません。

**CLIPScoreは、ゲートメトリックとしては使用されません。** これは概念の集合体として機能し、どの属性がどのオブジェクトに属するか、数、および関係を認識しません。ベリファイアインターフェイスには、既知の不具合であることが文書化されているため、誰も再導入することはありません。

| 述語 | `core/`内の11個の複合的な意思決定ポイントは、**ミューテーションテストされています。** 21個のうち20個のミュータントが排除され、[残りのミュータントの名前](scripts/mutate_predicates.py)は隠されていません。 |

| 閾値 | スプライトサブゲートの最小値と分散の制限は、**記録されたキャリブレーションのないハードコード化されたデフォルトです。** ホールドアウトや引用はありません。これらはプレースホルダーとして扱ってください。 |
| 実際の正典 | 出荷されるサンプル契約書は、**一般的な発明であり、実際のプロジェクトの正典ではありません。** 実際の正典をバインドすることは、意図的な人間の決定です。 |

このドキュメントの以前のバージョンで述べられており、測定によってサポートされなかった2つの主張について、ここでは修正し、黙って削除するのではなく、以下に示します。

- 三つの閾値は、*人間がラベル付けしたホールドアウトデータに対してキャリブレーションされた*ものとして説明されています。しかし、そうではありません。これらはデフォルト値です。
- 生成モデルは決して自分自身のゲートにはなり得ないというルールは、研究によってそれが証明されたかのように述べられています。それを裏付ける証拠は、**直接的なものではなく、むしろ収束的**です。つまり、二者択一の識別的なポーリングは、自由形式のキャプション生成よりも測定可能な限り安定しており、モデルは外部からのフィードバックなしでは確実に自己修正できず、自己認識は自己選好バイアスを追跡します。単独の研究で直接比較が行われるわけではありません。このルール自体は妥当ですが、その確実性は誇張されています。

## 信頼性と脅威モデル

- **アクセスされるデータ**：指定されたJSON形式の契約データ、入力として渡される画像、および指定されたディレクトリに書き込まれるプロベナンスレコードです。それ以外のデータは読み込まれません。
- **アクセスされないデータ**：あらゆる種類の認証情報は読み込まれたり、保存されたり、送信されたりしません。**テレメトリ、分析、または使用状況の追跡も行いません**。オプトアウト機能がないのは、オプトアウトする対象が存在しないためです。コアはネットワークライブラリを一切インポートしません。
- **ネットワークからのデータ送信**：コアからは何も送信されません。オプションの`[image]`と`[synth]`の追加モジュールは、その性質上、モデルホストにアクセスします。これが唯一のネットワーク経路であり、それらをインストールするかどうかは選択できます。
- **権限**：通常のユーザー権限のみが必要です。管理者権限の昇格、サービスプログラムのインストール、レジストリまたはシステム設定への書き込みは行いません。
- **注意すべき点（隠さずに開示）**：**ファイル操作はサンドボックス化されていません。**`--records-dir`と`--db`は、指定された場所に意図的に書き込みます。これはローカル優先のツールであるためです。書き込む場所を適切に指定してください。
- **エラー**：意図的な拒否には、コード、メッセージ、およびヒントが含まれており、**例外を発生させます（`assert`ではなく）**。そのため、`-O`はそれらを削除できません。スイートは、そのことを証明するために、`-O`の下で2回実行されます。予期しないエラーが発生した場合、トレースバックは`--debug`でのみ出力されます。

## サポート状況

`main`のみがサポートされている状態です。リリースチャンネル、バックポートポリシー、SLAはありません。これは、オープンに公開されたスタジオインフラストラクチャであり、サポート契約を結んだ製品ではありません。

## 構成要素の配置方法

`core/`はドメインに依存せず、拡散またはPyTorchのシンボルを一切インポートしません。ドメインプラグインは、正確に3つのものをエクスポートします：ジェネレーター、検証者のリスト、およびエンコーダールールセットです。新しいドメインを追加するには、`domains/`の下に新しいサブモジュールを作成するだけで、`core/`の内容は変更されません。GPUを使用しないスイートが、この主張を裏付けています。

```
src/pcraft/
  core/          contract · loop · gate · synth · optimize · receipt   (GPU-free)
  cli/           pcraft: synth | gate | bind | demo | replay | compile | sync-rules
  domains/       ── PLUGIN BOUNDARY ──
    image/       generators, the three verifier tiers, encoder rules, sprite subdomain
```

`domains/image/rules/`のエンコーダールールは、**検証済みのレシピデータベースから生成される**ものであり、手動で記述されたものではありません。また、生成ヘッダーが含まれています。バインドされたすべての資産は、契約ハッシュ、シンセサイザーアーティファクト、ジェネレーターとシード、検証者バージョン、および完全なアトムごとのゲートトランスクリプトを記録する**再現可能なプロベナンスレシート**を書き込みます。

設計の根拠、このリポジトリが評価される基準、およびすべての不可逆的なアクションに対する対応策は、[`STANDARDS.md`](STANDARDS.md)と[`COMPENSATORS.md`](COMPENSATORS.md)に記載されています。
